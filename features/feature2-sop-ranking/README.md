# Feature 2 · 미변경 설정값 대안 평가

`POST /api/setpoint-decision`의 `feature2` 결과에는 선정 후보, 분기 지표, 평가 근거 ID와 최종 권고가 들어갑니다.

1. [후보 선별](sop_ranking/score_selection.py)은 Feature 1 기준안이 변경한 설정값을 제외합니다. 나머지 설정값에서 서로 다른 두 개를 고르고 각 설정값의 −10%, +10% 방향을 조합합니다. 남은 설정값이 6개면 범위 적용 전 후보는 60개입니다. 두 목표값 모두 허용 범위에 드는 조합을 채점합니다. 모든 채점 요청과 첫 시험 순서를 고르는 요청에 Feature 1이 전달한 알람별 RAG 근거와 SOP 계획을 `alarm_rag`로 넣습니다. 각 대안의 Zoro `score`를 합계 1로 정규화하고, 누적 점수가 0.9 이상인 최소 후보 수를 선정합니다. `choice`로 선정 후보 중 첫 시험을 고릅니다.
2. [분기 비교](sop_ranking/evaluate.py)는 같은 체크포인트에서 Feature 1 기준안과 선정된 조합의 두 변경을 함께 추가한 분기들을 평가합니다.
3. [효율성 판정](sop_ranking/efficiency.py)은 RAG의 생산량·품질·복귀 적격 기준과 기존 벤치마크의 비용·추종 정확도 비교를 사용합니다. 비용과 정확도가 동률이면 생산 손실이 작은 쪽을 선택합니다. 더 나은 적격 대안이 없으면 기준안을 권고하고, 적격 결과가 없으면 운영자 검토로 반환합니다.

기존 알람 대응 화면의 `POST /api/zoro-agent`와 퍼지 시나리오 예제는 [알람 에이전트 데모](docs/AGENT_DEMO.md)를 참고하세요.
