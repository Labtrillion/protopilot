# **공장 경보 대응에 쓰이는 Zoro-1**

ProtoPilot은 화학 공정에서 경보가 울리면 센서값과 최근 변화를 Zoro-1에 보냅니다. 모델은 목표 생산량이나 반응기 온도처럼 제어기가 맞추는 값을 제어 목표 수치를 표준운전절차(SOP)를 바탕으로 조절합니다. 또한, ProtoPilot은 실제 선택된 제어 목표 수치와 별개로, 가능한 다른 제어 대체 방안을 고안하고 시뮬레이션한 결과를 확인함으로써 스스로 SOP를 업데이트할 수 있는 정보를 제공합니다. ProtoPilot의 성능을 확인하기 위해, 화학 공정의 반응을 모사하는 테네시 이스트먼 공정(TEP) 시뮬레이터에서 각 대응안을 시험합니다. 같은 상태에서 시작해 ZORO의 action plan과 다른 베이스라인을,  생산 손실 / 비용 및 시간 / 센서 수치 안정성 세 가지 측면에서 비교합니다.

**Zoro-1의 세 가지 판단 유형**:

- **Noul은 예 또는 아니오로 답할 질문에 ‘예’일 확률(0\~1)을 돌려줍니다.**   
- **Choice는 후보 중 하나를 고릅니다. 선택한 후보의 ID와 확신도, 후보별 확률도 돌려줍니다.**  
- **Score는 미리 정한 단계별 확률을 점수 하나로 환산합니다. 이 문서에서는 대응을 뒷받침하는 근거가 얼마나 충분한지 0\~2점으로 평가합니다.** 

| 시나리오 | 이 사례를 고른 이유 | Zoro-1에 묻는 내용 | 판단 뒤 조치 |
| :---- | :---- | :---- | :---- |
| **01 경보 두 건** | 여러 설비에서 경보가 겹칠 때 무엇부터 어떻게 조정해야 하는지 잘 판단할 수 있는지 (보통 사람이 한다면 불확실한 과정을) 대체 | Noul로 어떤 목표값을 바꿔야 하는지 묻고, Choice로 조정 방향과 폭을 고릅니다. | 선택한 조정안으로 목표값을 바꿨을 때의 공정 변화를 시험합니다. |
| **02 고온 오경보** | 센서 오류가 발생할 수 있음. 이럴때 별도로 잘 감지하여 대처할 수 있는지. | 온도, 압력, 냉각 상태를 함께 본 뒤 Noul로 목표값을 바꿔야 하는지 묻습니다. | 모든 목표값에서 변경이 필요할 확률이 50% 미만이면 그대로 운전합니다. |
| **03 생산 목표 불일치** | 기존 IDV처럼 공정 설비의 고장이나 외란이 발생한 상황이 아니라, 승인된 생산계획과 제어기 설정값의 불일치가 문제의 원인인 상황. 센서 상태만 보고 대응하지 않고, 계획 문서와 목표 변경 기록을 함께 확인하는지 평가 | Choice로 현재 생산 목표 유지와 승인 목표로 복귀 중 어떤 대응이 적절한지 고릅니다.  | 결과를 바탕으로 목표값 변경 여부를 추천합니다. |

# **01 여러 설비의 경보가 겹친 상황 (Feature 1 성능 검증)**

**Zoro-1 System 1 \| Noul로 변경 필요성 확인, Choice로 조정안 선택**

원료 A/B/C의 배합과 반응기, 분리기에 들어가는 냉각수 온도가 함께 변하도록 설정했습니다. 공정에 이런 변화를 주는 시험 조건을 외란이라 부릅니다. 이 사례에는 (외란) IDV 8, 11, 12를 적용했습니다. 반응기 온도는 120.12°C로 데모 경보 하한인 120.2°C보다 낮았고, 분리기 액위는 51.04%로 상한인 50.8%를 넘었습니다.

![][image1]  
**모델에 주는 정보:** 현재 울린 경보, 최대 2시간의 센서값 변화, 제어기에 입력된 목표값과 조작 명령, 자동 보호 기능의 작동 여부를 보냅니다. 모델은 외란 번호를 가린 상태에서 이 정보로 판단합니다.

**판단 기준**: 변경이 필요할 확률(Noul)이 50% 이상인 항목만 Choice로 조정 방향과 폭을 정합니다. 모델이 고른 조정 폭을 새 목표값으로 환산합니다. 모델 호출에 실패하면 미리 정한 규칙을 적용하고 오류 사유를 기록합니다.

**비교할 대응**: 경보가 울린 순간을 출발점으로 현재 목표 유지, 미리 정한 규칙 적용, Zoro-1 제안 적용을 각각 4시간씩 시험합니다. 공정이 자동으로 멈췄는지(트립), 운전 한계를 얼마나 오래 넘었는지 먼저 보고, 누적 생산 손실과 운전비를 비교합니다.

**확인한 기록**: 화면에서 반응기와 분리기 경보, 센서값을 확인했습니다.

**공개 데모 Feature 1 결과 (시나리오 4)**. 345.6분 고압 경고에서 Zoro-1은 생산 목표 −5%, 반응기 압력 목표 −2%를 제안했습니다. 4시간 비교에서 현재 목표 유지 분기는 운전 한계 이탈 0분으로 가장 많은 **91.30 m³**를 생산했고, 단위 생산 비용은 **10.23 USD/m³**였습니다. Zoro-1 제안 분기는 65.82분 이탈했고 89.86 m³를 생산했습니다. 실행 ID `60ecd985ce9c44159a776fa488318cb0`. [시나리오별 비교표](../README.md#시나리오별-베스트-케이스)

# **02 온도 센서 오류로 울린 경보 (Feature 1 성능 검증)**

**Zoro-1 System 1 \| Noul로 변경 필요성 확인, 필요할 때만 Choice 호출**

정상 운전 중인 반응기의 온도 표시값에만 \+35°C를 더했습니다. 실제 온도는 120.4°C였고, 센서 표시값은 155.4°C로 경보 상한인 150°C를 넘었습니다. 이 사례에서는 경보가 울렸을 때 생산량을 줄일지, 현재 목표를 유지하면서 지켜볼지 판단합니다.

![][image2]  
**모델에 주는 정보:** 고온 경보, 온도 표시값의 변화, 압력과 냉각 상태를 보냅니다. ProtoPilot에서는 실제 온도와 센서 시험 여부를 따로 확인합니다.

**판단 기준**: 모든 항목에서 변경이 필요할 확률(Noul)이 50% 미만이면 현재 목표를 유지합니다. 이때 Choice는 건너뜁니다. 온도가 계속 오르거나 압력 또는 냉각 상태가 나빠지면 다시 판단합니다.

**비교할 대응**: 현재 목표를 유지하는 안과 규칙에 따라 생산 목표를 낮추는 안을 비교합니다. 온도 한계를 넘었는지는 \+35°C를 더하기 전의 실제 온도로 확인합니다. 두 대응의 누적 생산량을 비교해 생산 목표를 낮췄을 때의 영향을 봅니다.

**확인한 기록**: 화면에서 고온 경보, 실제 온도, 센서 표시값을 확인했습니다.

# **03 교대 뒤 제어기에 남은 생산 목표 (Feature 2 성능 검증)**

**Zoro-1 System 1 \| Choice로 대응 선택, Noul로 적용 조건 확인, Score로 근거 평가**

교대 전에 증산 일정이 미뤄졌는데도 제어기에는 이전 계획의 높은 생산 목표가 남았습니다. 교대 직후 반응기 압력이 오르고 분리기 액위가 평소 범위를 벗어납니다. 이 교대 상황은 TEP에 기본으로 들어 있는 외란 28개와 별도로 설계했습니다.

![][image3]**모델에 주는 정보**: 경보와 센서값, 해당 표준운전절차를 모델에 보냅니다. 데모 설계에서는 제어기에 입력된 목표값과 변경 시각을 최신 승인 계획과 대조합니다. 화면에는 제어기의 생산 목표를 22.95 m³/h에서 26.5 m³/h로 바꾼 예시가 나옵니다.

**판단 기준:** Choice로 표준운전절차에서 검토할 대응을 고릅니다. Noul로 본 적용 가능성이 50% 이하이거나 Score가 1점 미만이면 근거를 다시 찾거나 운영자에게 검토를 맡깁니다.

**비교할 대응**: 경보가 울린 상태에서 현재 목표를 유지하는 안과 승인 목표로 되돌리는 안을 비교하도록 설계했습니다. 두 안 모두 표준운전절차의 필수 조치를 적용합니다. 압력이 정상 범위에 돌아오는 시간, 분리기 액위 편차, 승인 계획 대비 누적 생산량을 다음 Choice에 넣어 권고와 재확인 시점을 정합니다.

**구현 범위**: 현재 시스템은 경보에 해당하는 표준운전절차의 대응을 검토합니다. 승인 계획을 자동으로 비교하고 복귀안을 시험하는 절차는 데모 설계입니다.

**기록할 항목**: 승인 계획의 버전과 목표값, 모델 요청과 응답, 두 대응의 비교 결과, 권고와 재확인 시각

# **구현과 로그 위치**

모델 ID는 trillionlabs/Zoro-1입니다. POST /v1/systemone에 상태(state)와 질문(questions)을 보내면 답변(answers)을 받습니다.

Feature 1의 판단 ID, Noul 확률, Choice 선택, 변경 전후 목표값과 대응별 결과는 data/agent-trace.jsonl에서 확인합니다.

Feature 2의 요청과 응답은 /api/zoro-agent 응답의 sop\_stage.exchanges와 exchanges에서 확인합니다. 선택한 대응은 next\_action.choice에 기록됩니다.
